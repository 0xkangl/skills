# Test and Fix

以有效测试保护真实行为，完成「运行 → 评估 → 修复 → 回归」闭环。

仅在用户明确调用本 skill 时执行（如 `/test-and-fix`、`/kang-skills:test-and-fix`）；不得因发现测试失败而自行触发。

## 输入与范围

- `/test-and-fix`：当前项目，默认 CI 测试。
- `/test-and-fix ../api "../web app"`：指定多个项目，分别处理。
- `/test-and-fix [项目路径…] --all`（或 `全部`）：所选项目的全部测试。
- 加 `--push` 或明确要求推送：通过测试并满足下述提交条件后推送到远端；默认不推送。

从调用参数（`$ARGUMENTS`）和上下文解析路径与范围，不把参数直接当 shell 执行。未指定路径时定位当前所属项目；monorepo 按 workspace 配置确定包范围，不自动遍历无关兄弟仓库。仅在项目歧义或缺少影响结果的输入时询问。

## 1. 确定测试清单

读取各项目适用的 `AGENTS.md` / `CLAUDE.md`、测试说明和运行器配置。记录各仓库当前分支、HEAD、已暂存、未暂存及未跟踪文件的内容基线，用于区分已有改动和本次修复；保留已有用户改动。

- **默认 CI**：检查 CI workflow，追踪复用 workflow、本地 action、任务脚本及其调用链；纳入所有测试任务，包括条件触发、定时任务、矩阵与分片。记录工作目录、命令、运行时版本、环境变量与服务依赖，不能只挑一个 `test` 命令。纯 lint、类型检查、构建不是测试，但测试必需的准备步骤要执行。
- **全部**：在 CI 清单上补查各包清单、任务文件、运行器发现规则、测试目录及测试脚本，覆盖 CI 未调用的单元、集成、端到端等测试；排除依赖、生成物和无关脚本。不是执行仓库中的任意脚本；不盲目解除已有 skip/ignore，单列其覆盖缺口。
- **无 CI 测试**：明确说明，改用项目文档及配置中的测试入口；没有入口时查找实际测试并使用已有运行器，不臆造命令或为完成任务引入测试框架。未发现测试不算通过。

执行前简述每个项目的范围与命令清单，直接继续。等价重复入口可去重，不合并不同环境或参数的覆盖；平台、凭据或外部服务缺失的项仍留在清单中。

## 2. 运行并判断失败测试的价值

按项目既有方式准备环境，使用锁文件和声明的工具版本，以非 watch 模式运行清单；保留退出码与失败摘要。一个项目失败不阻断其它独立项目；共享服务或数据的测试避免并行干扰。不得运行与测试无关的部署、发布步骤。

**深入定位和修改前**，先读失败用例及其对应契约，判断：它保护什么真实行为？删掉会漏掉什么回归？

- **保留**：保护业务行为、公开契约、安全、数据完整性、边界条件或真实历史缺陷；简单、慢、难修或偶发失败不代表低价值。
- **可删除或合并**：需求已明确废弃；由其它测试等价覆盖且没有独立价值；仅锁定无契约意义的内部细节；或断言恒真、只验证 mock 自身等无法发现真实缺陷。先给出具体证据及替代覆盖（如有），再移除最小范围并同步直接相关入口，无需逐项请求许可。
- **价值不明**：默认保留。有效需求仍在但断言过时，应按需求修正测试；不能仅以当前实现作为正确性的依据。

不得通过 skip/only、吞错、放宽断言、降低覆盖率门槛、排除失败文件或盲目接受快照来换取全绿。环境故障不是删测理由；不借机清理无关测试。

## 3. 修复与回归

1. 按共同根因归组失败，先处理阻断测试的环境或配置问题；对保留测试以最小用例复现，结合日志和代码验证根因，区分实现缺陷、测试缺陷与环境故障。
2. 做最小修复，沿用项目规范，不顺手重构。偶发失败排查时间、随机性、并发、顺序和资源隔离；一次重跑成功不能证明修复。
3. 先跑失败用例及受影响套件，再在最终改动状态下重跑所选范围的完整清单；必要时绕过测试结果缓存，确保实际执行。新增失败继续循环。多项目共享代码变更后重跑受影响项目，不能沿用修改前的通过结果。
4. 持续推进直到通过；若缺少外部条件、存在无法判定的需求冲突或反复尝试无新证据，保留进展并报告具体阻塞、已试方法和所需输入，继续其它可独立完成的项。不得无限盲重试或伪称成功。

## 4. 验收、提交与推送

检查最终 diff，确认没有无依据削弱测试或覆盖用户改动。只有清单完整执行、实际有测试运行、结果通过且无未验证覆盖缺口时，才称「所选范围全部通过」，并进入提交与推送。命令退出 0 但零用例、仅缓存命中、存在漏跑矩阵或跳过项时说明限制；本地验证不能冒称远端 CI 通过。

- **提交**：逐仓库对照基线检查全部已暂存、未暂存及未跟踪改动。若有修改且全部由本次测试修复产生（含相关测试、配置和文档），明确暂存这些文件、核对暂存 diff，按项目提交规范提交；没有修改不创建空提交。存在任何其它来源或归属不明的修改则不提交，也不只提交本次部分；报告原因，保留工作区和暂存区。不通过删除、stash 或 reset 其它修改来满足条件。
- **推送**：仅用户明确要求时执行。先确保所选项目测试均通过，且待推送仓库所有代码修改均已提交（含未跟踪代码），提交内容与最终验证状态一致。若其它修改使自动提交条件不成立，停止推送并说明需先处理哪些未提交修改；推送要求不覆盖上述提交限制。无本次修改但已有待推送提交时也检查这些条件。
- 推送前核对当前分支、远端、目标分支及全部待推送提交；目标不明确时询问，不猜测。正常推送，不自动强推或改写历史；若需解决分支分歧，处理后重新验证受影响测试。推送后核实远端目标包含本次提交；失败时保留本地提交并报告，不声称推送成功。非 Git 项目仅报告测试与改动，不自动初始化仓库。

逐项目简报：**范围（CI / 全部 / 无 CI 回退）、实际命令与结果、修复内容、删测及理由、未运行或跳过项与阻塞、提交 hash 或未提交原因、推送目标与结果或未推送原因**；仅有真实计数时报告用例数。
