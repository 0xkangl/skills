# Docs Maintain

以当前实现和可核验证据维护项目文档，让读者准确理解如何使用、如何开发、还有什么未完成。

## 边界

- 默认直接修改请求范围内的文档；仅要求审查时只报告发现。只改文档及必要的文档导航，不为迁就文档修改业务代码、配置或测试，不自动提交或推送。
- 沿用已有文档体系、语言和权威来源，不强制补齐文件或套用固定模板。保持 `AGENTS.md` / `CLAUDE.md` 的正文归属、指针关系及目录作用域。
- **实现事实、规范要求、未来计划分开判断**：代码说明当前行为，不自动推翻产品契约、团队约束或未实现需求。冲突无法判定时保留要求，指出偏差；只询问影响处理的关键问题，其余继续。

## 1. 定范围，找证据

1. 读取适用的项目指令，检查工作区改动；保留用户已有修改。以指定路径或版本为准，未指定则以当前工作区为基准，不将本地实现写成已发布或已部署。
2. 用 `rg --files` 等列出范围内的文档与代码入口，包括相关模块文档；识别权威进度源、生成文件和归档。从文档中的具体断言追踪代码，不无差别通读整个仓库；全仓维护时先列出主要模块再逐项覆盖。
3. 对照依赖清单、命令脚本、配置定义、CI、接口注册、关键调用链和相关测试，核实安装启动、功能边界、业务状态与失败分支。检查功能开关、默认值、权限和外部依赖；存在函数、注释或 mock 测试不等于功能可用。
4. 双向核对：文档描述是否仍成立，当前重要行为是否漏写。为拟修改的事实、删除的事项和状态变化找到具体证据（文件/符号、测试结果或可追溯决策）；必要时查看局部 Git 历史，旧文档与提交标题仅作线索。

## 2. 按职责更新

以下为内容归属参考，优先沿用项目已有分工。

| 文档 | 保留并校准的内容 |
|---|---|
| `README.md` | 项目用途、当前可用能力、最短可行上手步骤、配置入口、使用限制与详细文档导航；设想不写成已实现 |
| `AGENTS.md` / `CLAUDE.md` | 项目特有且影响决策的约束、必要命令、目录职责和按需阅读入口；去掉重复常识、过时路径与任务流水账，保留仍有效的禁止项及例外 |
| `WORKFLOW.md` | 实际适用的开发、验证、评审、发布流程及其触发条件；核对命令、工作目录、前置条件与完成标准，不因尚未自动化就删除人工步骤 |
| `ROADMAP.md` / 既有进度源 | 当前目标、未完成事项、阻塞与下一步；区分待实现、已实现待验证、已验收，不编造优先级、负责人、日期或完成比例 |
| 其他关联文档 | 仅同步受影响的架构、接口、配置、部署说明与翻译；同一事实保留一份权威正文，其他位置用简短说明或有效链接引用 |

保持最小必要差异；合并重复内容，不为统一风格重写正确段落。生成文档或受保护区块按既有生成流程维护，不直接手改；生成来源不在本次授权范围或无法运行时，报告缺口，不伪造同步完成。

## 3. 清理过时内容与进度

- **已失效**：有证据表明功能已移除、方案已替代、问题已解决或任务已取消，才删除或修正对应描述；使用限制和仍有影响的迁移提示继续保留。
- **已完成**：有对应验收证据才更新完成状态。从活跃清单移出冗长执行日志，将仍有价值的结果、决策原因和验证入口压缩为短摘要；沿用已有归档、发布记录或 Git 历史，不另建重复台账。
- **尚未完成或不确定**：保留真实待办与阻塞。长期未更新、代码未搜到、单个测试通过，都不足以证明任务失效或整体完成；证据不足时说明待确认点。
- **历史与保留要求**：不将 ADR、发布说明、迁移指南及项目要求长期保留的计划当作垃圾。旧文件存在唯一有效知识时先迁入合适位置并修复引用；未跟踪或未提交的内容不能假定可从 Git 恢复。

删除或移动整份文档前检查入链、外部入口约定与保留要求，优先局部精简。不要把大量过时记录仅搬到另一份新文档，也不要追加本次清理的冗长日志或无意义的“最后更新”日期。

## 4. 验证与交付

1. 复核修改过的事实与状态是否有证据，检查文档之间是否矛盾；修复受影响的相对链接、标题锚点、导航和示例路径。
2. 对新增或修改的命令、配置示例做针对性验证：核对实际入口、参数和前置条件，能安全本地运行的执行验证；发布、迁移等有外部副作用的命令不为验证文档直接执行。使用项目已有文档检查或相关最小测试，不为纯文档整理新增工具链或盲跑全套测试。
3. 检查最终 diff（Git 仓库同时运行 `git diff --check`），确认未覆盖无关改动、削弱有效约束、误删未完成事项或引入无依据的“已完成”。无法验证的部分明确说明。
4. 简短交付：改了哪些文件、纠正和清理了什么、关键依据、验证结果及待确认项。无必要变更时明确说明；不默认生成额外审计报告，不将局部核查说成全仓已验证。
