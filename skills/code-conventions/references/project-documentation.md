# 项目文档规范

适用于项目初始化和文档维护；按项目现有文档体系维护事实与入口，不强制创建固定的三份文档。

完整索引见 [SKILL.md](../SKILL.md)。

## 指令入口与内容归属

- 进入项目时读取适用的根及目录级指令；按任务读取项目已有进度源，以及涉及功能、架构、安装或使用方式的 README 和详细文档。
- 新项目需要 Agent 指令时，使用目标工具支持的入口，记录项目定位、关键目录职责、工作边界、工作流导航、验证命令和必要文档指针；不为套模板创建空章节。
- 同一规则只维护一份正文，其他入口通过工具支持的引用机制指向它。已有项目沿用实际的 `AGENTS.md` / `CLAUDE.md` 归属，不自行翻转入口。仅写一行引用不代表所有宿主都会加载，应核实目标工具的支持方式。
- 仅保留长期稳定、经常使用、无法可靠推断或误判后果重要的信息。新增前合并同类规则；详细领域流程用文档链接承载，不在多处复制，不重复全局个人偏好。
- 项目约定可以细化默认工程偏好，但不能覆盖宿主指令层级、权限限制或用户明确的任务边界。

## README 与详细文档

- README 描述当前可用状态，安装命令、配置示例和使用方式应与实现一致。未实现的设想和待办放在项目已有的规划或进度源。
- 当前限制、已知问题和会影响使用的阻塞仍应在 README 的相关位置说明，不能为了形式上的“只写已实现”而隐藏使用限制。
- 对架构、接口和操作流程的详细说明维护在对应文档中，由 README 或项目指令提供入口。使用可移植的相对链接，避免个人机器路径。
- 配置、依赖、启动或安装命令、对外行为改变时，同步受影响的文档；不要求每次修改都重写所有文档。

## 进度与变更记录

- 沿用已有 ROADMAP、任务清单、issue 或其他进度源，同一事项只保留一个权威的当前状态；不另建竞争副本。
- 影响项目状态的实施、修复、文档变更，以及形成正式决策的调研，应同步既有进度源。只读查询和未改变状态的临时检查无需记录。进度源位于外部系统时，同步仍需符合已有授权。
- 完成状态必须有相应验收证据；实现完成但未验证的事项明确标为待验证，不写成已验收。不确定事项标明待确认。
- 清理失效和重复事项；最近完成、验证记录按项目约定排序和控制长度。只有项目明确规定时，才采用固定 20 条、北京时间或特定时间戳格式；时间戳从系统获取，验证记录写清对象、方式与结果。
- 长期发布记录沿用已有 CHANGELOG 或发布系统；自动生成的文件由既有流程维护。没有记录机制时，可沿用 Git 历史，不为归档强制新建文件。

## 修改指令文档

- 讨论或审查规范时只提供发现与建议；明确要求修改后，先更新规范的权威正文，再按新规则完成已授权的后续工作。
- 存在翻译或对照副本时，同步规则含义、例外与适用范围；供人查看的版本不需要成为运行时指令入口。
- 交付前检查文档是否反映最终实现、链接是否可用、示例是否适用于项目，以及是否存在重复或互相矛盾的规则。
