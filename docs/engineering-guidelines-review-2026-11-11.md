# Engineering Guidelines 三方官方规范复核

核对日期：2026-11-11。审查对象：`skills/engineering-guidelines/SKILL.md` 及中文对照。用户所写的「openapi」按 OpenAI 理解。本次同时审查全局指令管理、技能加载、模型使用及工程行为；已按结论同步修改两版正文。

## 结论与适用边界

现有技能的范围控制、授权延续、保护用户改动、根因分析和结果验证，与三家公开指引总体兼容。发现的问题主要是全局规则与技能的边界不明确、两项历史要求被精简弱化、测试措辞存在冲突，以及模型／运行时差异缺乏明确提醒。

这不是三家共有的一套「全局管理规范」认证。模型、Agent 宿主和项目约定是不同层次：Qwen 模型不等于 Qwen Code，Claude API 不等于 Claude Code，OpenAI API 不等于 Codex。相同模型接入其他宿主时，文件发现、权限和技能扩展字段仍由该宿主决定。不能根据公开提示建议推断完整内部系统提示词，或保证模型每次都遵守。

本次检索并打开官方页面，未以第三方教程或搜索摘要作为最终依据。下面把官方事实与本仓维护判断分别列明。

## 废弃、过度或不适用指令的处置

- **当前实际移除／替换：** 无条件新增回归测试的措辞；容易被理解为独立审批门槛的授权概括；把所有指令来源仅称为「文件」的限制。它们是措辞和适用范围问题，不冒称官方已废弃的 API。
- **旧版已经移除，继续不恢复：** 「Don't assume」的全面禁令、每个假设都说明、所有解释都列出、无部分开始、固定三步计划、单次抽象禁令、忽略实现时间成本、任何 API 都不能破坏、退出码为零却无输出必失败、无限验证循环。
- **不新增：** 强制多 Agent、固定重试次数、全任务统一 effort／thinking、全量依赖审计、全局配置自动改写、永久记忆文件、模型名单与价格。它们没有跨任务通用的官方依据，或超出本技能职责。
- **继续保留：** 根因、证据、授权、保护用户工作与相关验证。这些是交付要求，不因模型能力提高而自动过时。公开最佳实践的变化不足以证明可以删除用户仍有效的具体需求。
